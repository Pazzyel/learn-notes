# JVM内存空间

JVM把内存空间分为运行时数据区和本地内存

- 运行时数据：包括所有线程共用的堆空间和堆空间内的字符串常量池。已经每个线程私有的JVM虚拟机栈，本地方法栈，程序计数器（PC）
- 本地内存：包括元空间和元空间内的运行时常量池，和直接内存

JDK1.8之前元空间和元空间内的运行时常量池是属于运行时数据的

## 栈

JVM虚拟机栈：和调用栈的作用类似，调用函数时压入一个栈帧，函数返回时弹出一个栈帧。栈帧包括局部变量表（储存基本类型变量和对象引用），操作数栈（储存函数调用返回结果和计算中间结果等右值），动态链接（把当前类的方法引用指向运行时常量池的对应方法，可能是子类方法），和方法返回地址

本地方法栈：通过JNI调用的本地方法使用的栈，在Hotspot虚拟机中和JVM虚拟机栈合并

栈能使用的最大大小是有限的，不能扩展大小的栈在内存不足时抛出StackOverflowError，可以扩展大小的栈在无法扩展时抛出OutOfMemoryError

## 堆

堆是所有线程共享的一块巨大内存区域（远大于栈），几乎所有的非基本类型对象都分配在堆（逃逸分析优化下不会传到其它栈帧的对象可能分配到栈），JVM的堆是GC进行的主要区域

关于GC对堆的划分在GC部分介绍

无法分配新的堆空间或者GC耗时很长但只能回收很少的空间时，抛出OutOfMemoryError

## 方法区（元空间）

加载一个类时会解析其元数据并存入方法区，包括

- 类的完整结构，如类名、父类、实现的接口、访问修饰符，以及字段和方法的详细信息（名称、类型、修饰符等），通常是反射访问的数据
- 方法的字节码：每个方法的原始指令序列
- 运行时常量池：每个类独有的，由 Class 文件中的常量池转换而来，用于存放编译期生成的各种字面量和对类型、字段、方法的符号引用

JDK7后，类的静态变量，字符串常量池被移入方法区

JIT生成的代码缓存不保存在方法去，而是在Code Cache的区域

JDK7把方法区的实现从永久代调整位元空间，原本的永久代大小受MaxPermSize限制，元空间使用直接内存，MaxMetaspaceSize允许不指定，此时其大小只受到系统内存制约。JDK1.8之后，永久代被废除

## 运行时常量

包括

- 字面量，如各种基本类型和字符串字面量，在编译阶段可知
- 符号引用，提供把符号（一般是字符串字面量）定位到其对应的目标的功能（如把方法名称定位到实际执行的方法所在内存）
- 常量池表，类的常量，在类加载后存放到方法区的运行时常量池

## 字符串常量池

通过让多个内容相同的字符串引用引用内存的同一个不可变字符串对象，可以减少字符串占用的内存

字符串常量池是一个StringTableSize大小的HashTable

使用字符串字面量时，都会在常量池创建对应的字符串对象，直接把字符串字面量赋给其它引用，引用的是常量池的对象，使用new创建的字符串对象会根据常量池对象的内容在堆上分配一个新的字符串对象，使用itern()方法会（如果没有先创建）返回字符串对象的常量池引用

JDK1.7中因为方法区回收效率过低，常量池被移动到堆，因此常量池存的直接就是字符串对象本身

## 直接内存

直接内存不受堆的限制，直接通过JNI的方式在本地内存上分配，类似堆外内存

堆外内存就是把内存对象分配在堆外的内存，这些内存直接受操作系统管理

JDK1.4 中新加入的 NIO（Non-Blocking I/O，也被称为 New I/O）直接使用 Native 函数库直接分配堆外内存，然后通过一个存储在 Java 堆中的 DirectByteBuffer 对象作为这块内存的引用进行操作。避免了I/O过程在 Java 堆和 Native 堆之间来回复制数据

## 对象

### 创建

1. 类加载检查，检查能否在运行时常量池找到这个对象的类的符号引用的内容，并检查这个类是否有加载过，没有先执行类加载过程
2. 分配内存，此时需要找到一个足够大的空闲堆空间，通过碰撞指针或空闲列表的方式
    - 碰撞指针的意思是维护堆中的一个指针，该指针后面的所有内存都是未分配的，分配内存时计算分配的内存大小，并把指针移动对应偏移量到新的空闲地址。此方法依赖GC时整理出大量的连续空闲内存，CMS等不整理内存的垃圾收集器不使用这种方法
    - 空闲列表就是维护一个记录哪些内存块是空闲的的列表（一般按大小划分列表区间），找到一个合适大小的空闲块，分配内存并把剩余空闲块（如果还比较大）加回到空闲列表
    - 可能有多个线程尝试在同一个地址上分配内存，解决方法一种是CAS，另一种是TLAB，类似ThreadLocal，为每个线程分配一个小的私有的堆空间，优先使用这个空间，空间不够时才使用CAS在堆其它区域分配内存
3. 初始化为0值，除了对象头外的内存区域被初始化为0值
4. 设置对象头的内容，包括标记字段和类型指针
5. 执行init()方法，按照构造函数的形式设置对象的内容

### 内存布局

对象的内存包括对象头和实例数据，对象头包括

- 标记字段：对象的类型（是哪个类），对象的GC年龄，哈希值，线程持有的锁等
- 类型指针：类的元数据地址（在元空间）

根据是否开启指针压缩，对象头占用12~16Bytes，

对于某些包装类型如Integer，对象头占用的内存可能比其本身的实例数据更大

JVM要求对象的起始地址必须是8字节的整数倍，实例数据部分没有对齐，就会额外使用对齐填充，填充一些无效信息

### 访问定位

主流的实现有两者方式，句柄（Handle）访问和直接访问

- 句柄访问，堆中有一个单独的区域作为句柄池，栈帧的局部变量里的引用引用的是句柄地址，句柄包括对象实例数据指针和对象（类）元数据指针
- 直接访问，栈帧的局部变量里的引用引用的是就是对象在堆中的地址，包括对象头流的类型指针等和实例数据

Hotspot虚拟机中，一般对象使用直接访问，JNI中的对象引用使用句柄访问
