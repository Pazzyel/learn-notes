
# 计算机网络-补充

## 无线网络

### CDMA

CDMA依赖对每个节点分配唯一编码，对发送的数据编码让接收方可以识别发送方，多个节点就可以同时发送接收

把信号的一个bit时隙划分为M个微时隙，编码是以微时隙为时间单位变化的bit序列

对应第i个数据比特di，第m个微时隙编码cm，输出的bit信号`Zi,m = di * cm`，要从输出信号恢复原始数据bit，通过`di = SUM(1->M)(Zi,m·cm)/M`求得

在选择合理的不同CDMA编码下，即使不同发送方的信号混杂在一起，接收方也可以用同样的编码恢复出正确的发送方数据

### WiFi

IEEE 802.11 无线LAN俗称WiFi

802.11下的无线接入端必须先接入AP，AP是链路层设备（但通常的家庭路由器也承担AP的任务），AP+多个接入AP的无线设备称为BSS。一个AP需要分配一个单或双字的SSID用于标识AP，还需要分配唯一的信道号

802.11的2.4G频段定义11个部分重叠的信道，当两个信道间隔>=4个信道才是没有重叠的，最多没有重叠的信道配置有且仅有1，6，11

AP周期性发送信标帧，包含AP的SSID和MAC地址，用于向周围主机表示这个AP的存在，主机也可以自己发送AP探测请求帧，周围AP收到请求帧返回响应帧，也可以让主机获取AP的存在

主机获取周围AP的信息后选择一个AP接入，向对应AP发送关联请求帧，AP以一个关联响应帧返回。主机需要通过AP向子网发送DHCP请求报文获取自己在接入子网下的IP

AP鉴别是否是接入主机的数据报方法有MAC地址，应用用户名+口令等，通常AP和鉴别服务器是分离的，AP向鉴别服务器通信获取鉴别信息

#### 链路层协议：802.11

802.11的多路访问协议采用随机接入类型的CSMA/CA（带碰撞避免的CSMA，注意以太网LAN采用的应该是CSMA/CD），由于无线链路的局限，碰撞检测是很难的，因此不采用碰撞检测，而是使用一系列碰撞避免技术

802.11首先提供一种链路层确认的机制，与TCP类似，目标站点接收一个链路帧，必须在下一个短帧时间间隔SIFS发回确认帧，如果发送端迟迟没有收到确认帧，就重传该帧，数次重传仍未确认，放弃发送并丢弃该帧

发送端检测到信道空闲，在一个分布式帧间间隔DIFS发送帧。没有空闲则选择随机回退值，在侦测到信道空闲时-1，为0时才会发送帧

如果没有发送没有收到确认（可能就是因为链路碰撞），发送端在更大的取值范围随机回退并重复上述过程

802.11由于不会检测到碰撞而停止传输，必须尽可能避免碰撞，这就是为什么侦测到信道空闲时不是直接传输而是仅仅把计数器-1

##### 处理隐藏终端

无线链路可能造成隐藏终端问题，两个终端都在AP范围内而却不在对方终端的信号范围内，无法检测对方终端导致可能监听到错误的信道空闲状态

802.11使用**短请求发送**RTS和**允许发送**CTS控制帧解决此问题，发送端发送时需要先向AP发送RTS帧预约信道，这包括传输数据帧和ACK帧需要的总时间，AP以CTS帧广播作为响应，给发送方发送许可，给其他节点提示不要访问

#### 帧结构

注意AP是链路层设备，对于无线接入点和路由器，AP只相当于链路上的一个设备，有自己的MAC。802.11帧包括

- 帧控制：协议版本，类型，WEP（密码）等内容
- 持续期：RTS预约信道的时间和CTS提示等待的时间
- 地址1：目标地址
- 地址2：源地址
- 地址3：路由器地址，用于让无线接入点获知把帧发送到子网的路由器接口的MAC地址，路由器的帧到AP时，AP在其802.11帧的地址3放入路由器接口的MAC地址，无线接入点的帧到AP时，AP从802.11帧的地址3取出路由器接口的MAC地址，并生成对应的目标MAC为地址3的以太网帧
- 序号控制：用于确认该帧是首次发送还是重传
- 地址4：用于AP自组织模式
- 有效载荷
- CRC：校验

#### 其他功能

速率适应：如果一个节点连续发送2个帧没有ACK，就切换到速率更低但强度更强的协议；连续发送10个帧都有ACK（或上次降速的计时器超时），就切换到速率更高但强度更低的协议

功率管理：把帧的首部功率bit设置为1表示该无线接入点进入睡眠状态，AP接收后缓存应该发送给此接入点的帧，并在AP发送信标帧时唤醒节点并发送缓存的帧

#### 在AP直接移动

如果两个AP同属于一个交换机连接的子网，那么无线接入点不需要更新自己的IP，只需要更改交换机转发表把目标MAC为这个么无线接入点的数据报转发到另一个AP

一种方法是一个AP检测到新的无线接入，就广播源MAC为该无线设备的数据报，交换机检测到后就更新自己的转发表

### 蓝牙

802.15.1俗称蓝牙，以TDM方式工作在2.4GHz波段，每个时隙625us，时隙切换时在79个信道随机变化，称为**调频扩展频谱**，把信号扩展到整个频谱

802.15.1是自组织的，包括1个主节点，至多7个从节点，至多255个寄放设备，主节点可以在每个奇数时隙发送，从节点只能在主节点与其通信的下一个时隙向主节点发送，主节点还可以更改节点为寄放/活动状态

### 蜂窝因特网

蜂窝语音网，每个基站BTS以一个六边形的范围向周围区域提供信号接入，一个基站控制器BSC连接并管理几十个基站，组成基站系统BSS，一个移动交换中心MSC通过于BSC的连接，连接数个BSS

3G蜂窝因特网，对于管理多个BTS的无线电物理控制器RNC，除了接入MSC用于语音网，还接入服务GPRS支持节点SGSN，SGSN还以MSC交互提供用户认证和切换，多个SGSN接入网关GPRS支持节点GGSN，GGSN接入公共因特网。3G使用直接序列宽带CDMA（WCDMA）

4G蜂窝因特网：4G是全IP的，和3G语言和数据流量分离不同，4G的语言和数据都承载在IP数据报。4G网络的路由转发是SDN的，控制和数据分离。4G网络的组成包括

- UE：用户设备
- eNodeB：4G的无线电网络控制器，和多个基站相连，在UE和PG-W转发数据报，UE的数据报在此封装为加强的数据报，通过全IP强化分组核（EPC）以类似IPv6隧道采用的方法在IPv4设备上传输，隧道提供QoS等服务
- 分组数据网络网关PG-W：给UE分配IP，保证QoS，是隧道的端点，也进行数据报的封装/解封
- 服务网关S-GW：UE流量要通过此传递
- 归属用户服务HSS：提供UE的订购信息，身份信息等
- 移动性管理实体：执行连接和移动性管理，需要HSS的订购信息

4G LTE在下行信道采用FDM，TDM结合，称为正交频分复用OFDM，当一个移动节点被分配更多的频段和时隙，就能获得更大的速率（频段轴和时隙轴相正交，数据可以看成面积）

### 移动管理

要使得移动对于网络层是透明的，移动过程的IP不应该改变

移动设备所属的固定子网叫归属网络，移动设备拥有在归属网络的永久地址IP，移动设备连接的非归属网络的子网称为外部网络。归属代理负责管理归属子网下的所有移动设备（无论这个设备在哪），外部代理负责管理当前子网下的所有不归属于当前子网的移动设备

#### 间接路由选择

一个节点移动到外部网络，向当前外部代理注册，获得自己的转交地址COA（节点在当前外部网络的IP），离开时取消注册。外部代理收到注册请求后，通告归属代理此节点的COA

当一个外部服务器的响应到达时，首先根据永久地址寻址，也就是会到达归属代理处，归属代理根据COA，封装IP数据报（类似IPv6隧道）并转发到外部代理，外部代理解封再转发给设备

#### 直接路由选择

在服务端网络添加一个通信者代理，和间接路由选择不同的是，通信者代理向归属代理查询当前移动设备的COA，随后服务端响应到达通信者代理后直接封装送达外部代理并解封，省去了通过归属代理转发的消耗

还需要解决移动的情况。由于通信者代理仅在会话开始时询问COA，因此当前COA指向的外部代理将被做为锚代理，如果移动设备离开了这个外部网络并接入新的外部网络，除了重新通知归属代理，还要通知给锚代理其的新COA，因此通信者代理和锚代理的通信就可以被转发到新COA

#### 移动IP协议

以上操作在移动IP的规定下完成，定义了以下三部分

- 代理发现：移动设备获取新的外部网络外部代理的身份。代理可以代理通告，外部代理周期性广播类型9（路由器发现）的IMCP报文（包含外部代理IP），让设备获取外部网络信息。此ICMP报文是扩展过的，添加了各类要求bit，数个COA地址等（外部设备选择其中一个作为其COA）。移动设备也可以主动广播代理请求，收到请求的外部代理向此节点单播一个代理通告
- 向归属代理注册：移动设备向外部代理发送注册请求（UDP，端口434），包含COA，归属代理IP（HA），移动设备永久IP（MA），注册TTL和标识。外部代理记录器永久IP，添加一段封装格式要求并发送给归属代理（UDP，端口434）。归属代理建立移动设备永久IP-COA的映射，并发送回答给外部代理，外部代理把回答转发给移动设备
- 数据报的间接路由选择

蜂窝电话网的原理类似，用户的电话号码对应永久IP，用户接入的临时漫游号码对应COA，归属代理相当于归属位置注册HLR，外部代理相当于访问者位置注册VLR，电话在MSC间切换还会让初始MSC变为锚MSC，或者之间人旧MSC把呼叫转发到新MSC

## 网络安全

通过密钥和加密算法（算法是公开的）加密明文，传输过程传输密文，接收方根据密钥解出明文

### 块密码-对称块加密算法

把报文分成k bit的块，每个块又分成m bit的子块。m通常足够小，可以储存所有的m位二进制映射（密钥），对于m位二进制明文，映射表将其映射位m位二进制密文，每个m位的小块通过乱函数（公开的）打乱顺序，重新重复加密过程n次，就可以得到k bit的密文。这里需要保密的只有映射关系，也就是密钥。要求加密数据的长度必须是块长度整数倍，如果不是使用填充

典型的块密码如AES-128/192/256（数字代表密钥长度），使用k=128bit的比特块

为了让相同的明文可以被加密位不同的密文，还需要额外操作。设定m(i)为第i个明文块，s(i)是密文块，发送方还生成一个随机的k bit的串（初始向量VI，记作c(0)）。密文计算`c(i) = Ks(m(i) XOR c(i - 1))`，c(i)解密得到m(i) XOR c(i - 1)，由于之前已经接收过c(i - 1)，`m(i) = m(i) XOR c(i - 1) XOR c(i - 1)`以解密，其中和其他密文一样，c(0)是明文发送的

### 公开密钥的加密-非对称加密算法

如何在两端共享密钥呢？由于在对方没有获取到密钥前，是不可能解密报文的，因此无法通过加密密钥报文的形式共享。一种简单的解决方法是使用不共享密钥的加密算法，也就是**公钥/私钥**法来加密密钥报文

接收方有两个密钥，可以暴露的公钥K+和需要保密的私钥K-，公钥用于加密，私钥用于解密。发送方需要发送时，先明文取得接收方的公钥，c(i) = K+(m(i))，密文传输给接收方后用私钥解密m(i) = K-(K+(c(i)))

这种方法只能加密报文，但不能让接收方获知报文是否来源于真正的发送方，因此还需要数字签名技术

#### RSA算法

RSA密钥确定的流程如下

1. 选择两个大质数p，q，pq至少是1024bit的数量级
2. n = pq，z = (p - 1)(q - 1)
3. 选择e < n且e与z互质，e用于加密
4. 选择d使得ed mod z = 1（也就是ed - 1可以被z整除），d用于解密
5. 公钥是(n, e)数对，私钥是(n, d)数对

对于明文m，密文c，加密是`c = m^e mod n`，解密是`m = c^d mod n`，此算法能有效的稳定加密/解密，其原理来呀与模运算的特性

解密的结果`(m^e mod n)^d mod n = m^ed mod n`，在数论中有定理：质数p，q，n = pq，z = (p - 1)(q - 1)，x^y mod n = x^(y mod z) mod n，而RAS规定ed mod z = 1，因此m^ed mod n = m mod n，由于n很大，因此m mod n = m，成功解密。从原理可以得出调换公钥，私钥的位置，RSA也能正常工作

RSA的安全性依赖于公钥的n无法被快速分解（至少是现在）为p和q，从而无法通过公钥e推导出私钥的d

RSA算法的复杂程度比AES等使用共享对称密钥的算法大很多，效率较低，因此通常不直接用于加密数据报，而是用于**加密其他算法的共享密钥**（如AES）

### 报文完整性

对于接收的报文，需要确定两件事，一是报文是否来源于正确的发送方，二是报文是否没有被篡改

#### 散列函数

对于报文内容，使用散列函数（哈希函数）计算出一个哈希值（称为报文鉴别码MAC，不加密），理论上不同的内容哈希值必然不同，注意TCP等校验和的哈希函数十分简单，不一定可靠。常用的哈希算法有MD5（存在漏洞），SHA家族等。注意这些算法只把明文转化为哈希密文，不提供解密的手段，因此只用于判断

鉴别发送方，发送方只需要使用鉴别密钥s，附加到明文m形成m + s，计算哈希H(m + s)，形成扩展报文(m, H(m + s))，接收发使用同样的方法计算H(m + s)并比对即可。路由器间的共享的鉴别密钥可以通过RSA等传输，或甚至通过物理手段配置

#### 数字签名

如何确认某方是否签名过一个报文？利用RSA，发送方可以使用私钥对报文加密，发送密文给接收方后如果接收方可以用公钥解密，就说明发送方确实用了其秘密的私钥签名了报文。由于RSA的效率问题，通常不是对整个报文加密，而是对报文内容得到的MAC加密，在传输时传输这个加密的哈希值，接收发收到报文后计算哈希值并解密报文签名的哈希值，如果一致说明是正确的签名

这依然有一个问题，如何确定接收方获取的公钥是正确的发送方的公钥而不是伪造方的公钥？因此需要把公钥和特定实体绑定，通过认证中心CA完成，一个CA验证了某个实体的身份就颁发一个绑定实体身份-公钥的证书，也就是CA证书，并由CA对CA证书签名（使用CA的私钥）。发送方发送其CA证书，接收方用CA的公钥验证签名并提取发送方的公钥。很明显可靠性来源于CA的可靠性

一个CA证书可能包含：版本，序列号，CA的签名，CA的名称，证书有效期，实体名称，实体公钥等字段。对于很常见的HTTPS连接，可以在浏览器查看CA证书的内容

#### 端点鉴别ap4.0

鉴别报文是否是来自对面，首先需要判断对面是否活跃，接收端使用一个不重数R（其在整个ap4.0的生存期只使用一次），使用发送方公钥加密并发送给发送端，发送端解密得到R，在响应时用接收方的公钥加密R并发送给接收方，接收方解密并核对R，一致就说明是正确的端点

R不会被重复使用，因此如果入侵者截获发送方发送的带有R的密文并尝试使用同样的密文伪造请求，接收方会拒绝这个请求

### 应用层：安全的点对点连接

点对点连接的安全需要关注四个特性

- 机密性：数据报明文不会暴露
- 发送方鉴别：应该能够验证发送方的身份
- 报文完整性：报文必须不被篡改
- 接收方鉴别：应该能够验证接收方的身份

一般情况下，使用SHA，MD5等对明文生成哈希值，用自己的RSA私钥（发送方鉴别）加密哈希值，完成了数字签名，提供了发送方鉴别，报文完整性服务

接下来对以上的内容用AES等对称式加密算法加密，密钥用对方的RSA公钥加密（接收方鉴别），完成了机密性，接收方鉴别

对方只需要用自己的RSA私钥解密，计算明文哈希并于用对方公钥解密出的哈希比对即可

电子邮件加密方案PGP采用类似的原理

### 传输层：安全的TCP-SSL

SSL是应用层和传输层的中间层，程序使用SSL套接字发送把数据传入这个中间层，加密后使用TCP套接字发送，建立SSL连接流程如下

1. 客户端连接服务端，先明文发送其支持的加密算法和客户端不重数（不重数用来防止使用相同密文重复请求的攻击（重放攻击））
2. 服务端选择一种对称加密算法（AES），一种不对称加密算法（RSA），一种哈希MAC算法（SHA），把选择的算法，服务端CA证书，服务端不重数发送
3. 客户端验证证书，提取服务端公钥，生成前主密钥PMS，用服务端公钥加密PMS并发送
4. 使用相同密钥导出函数，两端独立从PMS和不重数计算主密钥MS，并切分成四个密钥，每一端都有一个加密密钥和MAC密钥
5. MAC以记录为单位添加，有序号。此后的SSL记录数据+数据+MAC密钥会计算哈希值后得到MAC，把数据+MAC（SSL记录数据不加密）用加密密钥再加密成完整加密的TCP报文，对方使用同样的密钥解密报文，使用同样的MAC密钥计算MAC并比对
6. 客户端要发送所有握手报文的MAC，服务端同样发送所有握手报文的MAC，验证握手过程没有被入侵

由于不重数的存在，SSL连接仅在当前活跃阶段有效，任何采用相同不重数的请求都被拒绝

断开连接时在SSL记录的类型字段指明这条记录是否用于关闭SSL，虽然记录段以明文发送，但MAC保证其不被篡改

### 网络层：IPsec

虚拟专用网络利用IPsec等技术在对公共网络物理设备上的流量加密，使得虚拟专用网络内的流量在数据的意义上是和公共网络隔离的

IPsec使用类似隧道的技术，把IPsec首部和数据报加密后作为IPv4的有效载荷封装为一个IPv4数据报，使用正常的IPv4网络层转发服务。IPsec在源和目标创建的网络层逻辑连接称为安全连接（SA），SA是单工的。需要创建SA就要维护SA的状态信息，包括安全参数索引SPI，SA源和目的IP，加密类型，加密密钥，哈希算法类型，鉴别密钥

一个使用虚拟专用网络的组织在安全关联数据库SAD储存所有的SA信息，在安全策略库SPD指示对数据报的加密/解密操作

实际IPsec数据报的构建从普通IPv4数据报开始，在原始数据报尾部加上ESP尾部（包括填充（因为加密报文必须是块长度整数倍），填充长度（用于删除填充），下一个首部信息），使用SA规定加密算法和密钥加密整个数据（初始数据报，尾部），然后加上ESP首部（SPI，序号信息），然后再对整个内容（首部，初始数据报，尾部）使用SA规定算法和密钥计算MAC，附加到尾部，然后在头部添加新的IPv4首部，就成为了新的IPv4数据报

新的IPv4数据报的源和目的仅仅是SA的两端而不是原始IPv4数据报的IP，协议号设置为50表示ESP协议

因特网密钥交换IKE用于自动的完成多端SA信息的交换共享，由两次交换组成，第一次交换用Diffie-Hellman在路由器间生成双向的IKE SA（加密+鉴别的信道），创建用于IKE SA的加密鉴别的密钥和IPsec SA的主密钥；第二次交换通过安全的IKE SA把签名的报文发送给对方透露双方身份，协商IPsec的加密鉴别算法，并生成双向的SA

### 链路层：加密LAN

初始802.11的WEP协议十分简单，没有密钥分发机制，加密使用40bit的对称密钥Ks+24bit的向量流IV（随着帧编号编号而有规律变化）形成64bit密钥。RC4流密码（对于初始密钥(Ks,IV)生成(Ks，V1),(Ks，V2)......的密钥流用于每一帧的加密）加密数据载荷和CRC，加密和解密的方法仅仅是简单的和密钥XOR。理论上RC4密钥流不应该有重复的密钥，但算法的缺陷导致出现重复的概率很高。攻击者发送明文，截获密文就可以得到某个64bit密钥并推导出后续的流，因此密钥只要重复出现就不再安全

802.11i提供了更完善的加密方法，特别是鉴别服务器的加入，一个鉴别服务器可以服务多个AP，流程是

1. 发现：AP通告其存在和加密+鉴别形式，客户请求其希望的加密+鉴别形式
2. 相互鉴别，生成主密钥MK：客户和鉴别服务器通信，使用可扩展鉴别协议EAP，一般通过数字签名+不重数完成
3. 生成成对主密钥PMK：客户，鉴别服务器分别从MK生成PMK，服务器向AP发送PMK，此后客户和AP就有了共享的PMK
4. 生成临时密钥TK：客户，AP用相同算法从PMK生成实际用于链路帧加密的TK

### 防火墙

防火墙分为3类

- 传统分组过滤器：根据协议栈各层的首部信息过滤，比如IP地址，端口，TCP ACK等
- 状态分组过滤器：传统的方法只根据固定的静态规则过滤，状态分组过滤维护一张连接表（由内部发起的TCP连接），动态地只允许连接表内的流量通过
- 应用程序网关：使用独立的网关服务器实现，除了首部以外还可以检查数据内容（深度分组检查），可以根据用户身份过滤，流量必须经过网关中转

入侵检测系统IDS利用特征或异常进行攻击检测，特征检测流量是否符合某种攻击的特征，异常判断流量是否不属于正常情况

## 流媒体

### 流式视频

六式视频对带宽敏感，对延迟不敏感，有三种

- UDP流：以恒定的视频比特率的速率向网络发送UDP报文
- HTTP流
- HTTP DASH自适应

HTTP流使用HTTP协议，客户端应用有一个缓冲区，缓冲区的视频量超过阈值时应用才播放视频，这个阈值应该<=缓冲区大小

TCP速率>视频比特率时，缓冲区最终会填满，这会导致客户端无法接受新的报文，因此限制了速率（利用rwnd），用户暂停视频也会导致这种情况

HTTP流利用HTTP字节范围首部请求视频流的字节范围，用户重定位视频或退出视频会导致缓冲区内已经传输的数据被浪费，因此缓冲区也不宜过大，HTTP DASH在之前已经介绍过，利用当前速率自动请求适合比特率的视频

### 实时音频

实时音频对延迟敏感，由于实时性也不应该重传，因此一般使用UDP而不是TCP，因为TCP的ACK机制增加了时延且TCP的拥塞控制可能把速率降低到接收方消耗比特率之下

对于UDP可能产生的丢包问题，对于实时音频轻微的丢包1%~20%是可以接受的，还有前向纠错FEC等机制用于从丢包恢复

实时音频要求端到端时延<400ms，接受方忽略超过时延的分组到达。时延尤其是排队时延不是固定的，因此需要特别的手段消除时延抖动

对于NAT的情况，两个客户端无法直接通信，可能需要无NAT的中继

#### 消除抖动

提供对块添加时间戳和接受方延迟播放来消除时延抖动

利用播放时延减少抖动，对于分组的时间戳t，经过t + Δ的时间才开始播放，在t + Δ之前到达的分组顺利播放，之后的丢包

Δ可以是动态的根据当前时延进行变化，，设分组发出的时间（戳）t，接受时间r，播放时间p，预估时延d，可以用上一个预估时延加上当前分组的数据求得下一个预估时延`di = (1 - u)di-1 + u(ri - ti)`，其中u是常量（如0.01）。设平均估计时延偏差v，同样可求得`vi = (1 - u)vi-1 + u|ri - ti - di|`，用这两个值估算p，`pi = ti + di + Kvi`，K是正常量（如4），`Δ = pi - ti`动态变化，同一话音突峰期的播放时刻`pi = ti + Δ`

#### 丢包恢复

有二种办法

第一种是前向纠错FEC，利用冗余的信息来完成丢包恢复，比如传输n个组就传输一个异或和冗余块，就可以恢复一个丢包，n越小恢复能力越强，占用的带宽也越多。还有一种冗余信息是额外传输一段低比特率的音频版本，对第n个分组包含n-1的低比特率版本和n的正常版本，有丢包可以使用下一个分组的低比特率版本

第二种是交织，把原本在一个块的音频分成多个单元，每个单元储存在不同的块，按一定的规则分散连续音频块的顺序，接收时按照规则恢复，如果丢包，那么丢包的音频被分散在各个段，减小了感知

#### 实时音视频协议

##### RTP

RTP是应用层协议，通常运行在UDP上，RTP首部包括有效载荷类型7bit（如MPEG4等音视频流的类型），序号16bit（用于丢包检测和恢复），时间戳32bit（数据分组中第一个字节的采样时刻，，每个采样周期+1，用于消除抖动），同步源标识符32bit（标识RTP流的源，两方的该值应当是不一样的）等，通常12字节

##### SIP

SIP会话发起协议也是应用层协议，可以运行在UDP或TCP上，使用端口5060

建立STP呼叫需要发送INVITE报文，包含目标SIP地址，源IP，源连接端口，源要求的编解码格式。接受方的响应包括状态码，接收方IP，接收方端口和编解码格式，收到响应后发送方发出一个ACK。如果要求的编解码格式对方没有，可能状态码为606不可接受并返回可用的格式.建立阶段的三次握手均使用5060端口，实际的连接使用报文提供的端口

SIP地址类似电子邮件地址，要从SIP地址获取对方IP，需要利用SIP注册器，一个活跃的终端向注册器报告当前SIP地址的IP地址（有一定的有效期），请求IP时向SIP代理请求，SIP代理请求可能的SIP注册器获得地址并返回（类似DNS解析）

### 网络管理

不同类型的流量可能需要不同类型的网络服务和不同优先级

漏桶机制可以管理向网络发送分组的速率，用一个桶装令牌，桶大小固定，新的分组要传输必须从桶中取出令牌，如果令牌产生的固定速率小于分组发送速率，分组发送速率就被限制，而桶的大小限制了一瞬间能发送到网络的分组数目。还可以同时串联使用多个漏桶，它们生成令牌的速率（峰值速率桶可能是1500/s，平均速率可能是6000/min）不同，用于管理峰值速率和平均速率

一种类型的流量（通过IP的服务类型字段等）被分组，打上标记，并由测定器监管，对不合规的流量行为处理（可能是延迟或丢弃），对于不同类型流量的调度，可以采用加权公平循环，对于同属于一种类型的流量，它们的服务质量是相同的

即使限制了某些低优先级的流量，高优先级流量如果需要的资源超过网络能提供的资源，显然应该限制其中一部分确保另一部分，由于分组公平性无法解决这个问题，因此还有QoS技术，通过QoS请求预约网络带宽资源。发起预约是链路可能有足够的资源并得到呼叫准入，如果资源不足就被阻塞。呼叫建立协议和资源预留协议用于实现QoS
